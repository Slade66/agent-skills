# Skill：原样分类

## 一、任务目标

把原文的各个段落按中心意思归入若干 `##` 章节，章节标题根据内容拟定。

产出一份新文档：原文的每个段落恰好出现一次、一字不差，只是被分到了各个章节里。

## 二、硬性规则

1. **禁止修改任何段落和句子。** 只做分析和归类，不做改写：原样搬运，不润色、不合并、不拆分、不删减、不改标点、不改错别字。

2. **原文件保持不动。** 结果输出到同目录的新文件，文件名为“原文件名（整理）.md”。

3. **不新增内容。** 除了 `##` 章节标题和章节组之间的 `---` 分隔线，不添加任何东西：不加 frontmatter，不加 `#` 总标题，不加说明（“以下是整理结果”之类的文字）。

4. **每个段落恰好出现一次。** 不重复，不遗漏。原文里内容相同的两个段落，算两个段落，都要保留。

5. **分类要细，标题要具体。** 章节数量按内容的复杂度灵活决定。不要用“……与……”这种笼统的标题；一类只讲一件事。内容太少、归不进任何一类的段落，统一放进文末的“其它”章节。

6. **混合主题的段落不拆分。** 一个段落里混了多个主题时，整段归入它想表达的核心主题，并记下这些段落的编号和归类理由，在完成后的自查中一并汇报。

7. **章节顺序：能递进就递进。**

   - 把有逻辑递进关系的章节排在一起，成为一组，按递进顺序排列。判断标准：后一章要以前一章为前提，调换顺序就读不通。

   - 组与组之间用 `---` 隔开，`---` 单独成行，前后各空一行。

   - 无法纳入任何递进关系的章节，合在一起排在各组之后，作为最后一组，与前面的各组之间同样用 `---` 隔开。

8. **章节内的段落保持原文的相对顺序。** 同一章节里的段落，按它们在原文中出现的先后排列。

## 三、执行步骤

1. **切分段落。** 先把原文按空行切成段落清单并编号，告知用户共有多少个段落。原文自带的标题行和单行的标点符号不单独编号，随它们相邻的段落一起归类。

2. **拟定标题与顺序。** 通读全部段落，识别各段的中心意思，拟出章节标题，判断哪些章节能逻辑递进并分组，给出“段落编号 → 章节”的归类方案和章节的排列顺序。

3. **脚本搬运。** 用脚本按归类方案读取原文并写出新文件，不要手打复述，以免改字。段落内部的换行、缩进和标点都保持原样；段落之间用空行分隔；章节组之间插入 `---`。

## 四、完成后的自查清单

1. **核对段落。** 用脚本排除新增的章节标题和 `---` 分隔线，再按内容及出现次数核对原文段落与输出段落，不比较排列顺序。

2. **修正差异。** 如有遗漏、重复或改动，重新生成并核对，直到所有原文段落都完整且仅出现一次。

3. **报告结果。** 向用户报告原文段落数、输出段落数、差异情况和最终结论：

   | 核查项 | 结果 |
   |---|---|
   | 原文段落数 | |
   | 输出段落数 | |
   | 遗漏、重复或改动 | 无 / 具体内容 |
   | 最终结论 | 通过 / 未通过 |

4. **汇报需要用户留意的情况。** 包括混合主题的段落（编号和归类理由）、归入“其它”的段落。
